# 阶段摘要与上下文质量模式

## 1. 要求与状态

用户要求阶段性压缩数据，避免询问时上下文和 token 持续膨胀，同时支持“高”和“最高”模式以投入更多分析。本地提案已实现按范围生成的事实摘要、三档输入字节预算、原文核对和单次模型调用。下文的持久化摘要索引、模型语义总结、多批次核验和模型专用 token 计数仍属后续设计。Markdown 接续包沿用独立的导出策略。

本地提案输入上限按标准、高、最高分别为 48、96、160 KiB，计量最终模型请求体的 UTF-8 字节，包括系统说明、协议字段、结构化输出定义（Responses）、用户问题、摘要及工作区明细。输出上限为 4096 token。页面与代理使用同一组装函数。必要节点和行动索引超过预算时需要收窄范围或调整档位，代理在转发前再次检查。切换档位沿用当前连接和模型。


区分三个概念：文件压缩节省存储和传输；语义摘要减少每次模型需要阅读的内容；检索决定本次展开哪些原始证据。压缩包不能直接解决模型上下文过长的问题。摘要具有信息损失，因此保留可回查来源与必要原文，不用摘要替代原始事实。

## 2. 分层资料

| 层 | 内容 | 读取方式 |
| --- | --- | --- |
| 当前状态 | 当前目标、已确认约束、锁定项、计划版本、未决问题 | 本次相关范围内优先读取，保持简短 |
| 阶段摘要 | 一段讨论、一个里程碑或一周/月的主要变化 | 通常作为历史上下文入口 |
| 主题索引 | 论文、学科、能力维度的摘要目录和证据位置 | 先选择相关主题，再逐层展开 |
| 原始证据 | 文件版本、具体片段、自述、测试结果、原始讨论 | 针对问题按需读取 |

每份摘要记录学习空间、范围、截止时间、源记录 ID 与版本、生成方式、摘要格式版本和有效状态。内容至少包括事实、决定、依据、变化原因、分歧、未验证假设和下一步，不把自述变成已证实结论。

确认的截止日、锁定项、用户更正等约束由结构化状态提供；统计数值从实际记录计算，不能依赖模型概括后再次累加。索引中只保留引用，避免在每一级重复复制相同证据。

## 3. 阶段压缩时机与更新

- 一段讨论形成明确决定、一个里程碑结束、用户主动收尾时，建立接续摘要。
- 周/月总结只在需要复盘且有新内容时生成；没有变更不重复调用模型。
- 准备发起长对话请求时，先检查已有摘要和输入预算；接近预算时，将较早讨论归入阶段摘要，保留近期交流和当前问题。
- 修改来源、用户纠正判断、撤销授权或删除资料时，相关摘要需失效、重建或清理；同一事实不能继续从陈旧摘要返回。
- 摘要按源版本集合、范围和策略版本缓存；只刷新受影响节点，不每次全量重算全部学习空间。生成期间来源改变的结果不能标成最新。
- 防止反复“摘要的摘要”导致失真：重大总评及争议判断回查原始证据，定期或在更正后重新建立相关主题摘要；不得只从上一份总评推断能力继续提高。

本地助手可以在用户请求的整理过程中输出摘要及其清单；网站接受导入时标明来源。网站模型生成或更新摘要属于模型调用，应计入本次预算并展示，不能把同步行为变成隐藏的付费任务。无可用模型或未选择模型调用时，可先生成确定性的事实摘要并保留待总结标记。

## 4. 三档模式建议

| 模式 | 使用场景 | 内容与分析策略 |
| --- | --- | --- |
| 标准（默认） | 日常讨论、任务调整、快速查看 | 当前状态、近期对话、相关阶段摘要和少量必要证据；证据不足时说明缺口 |
| 高 | 论文阶段评估、跨周复盘、复杂计划调整 | 扩大相关证据覆盖，回查关键结论，检查不同材料的冲突与备选方案 |
| 最高 | 重要阶段总评、长期方向重定 | 在所选范围内分维度读取与核验，分批分析后综合，额外检查遗漏、反例和来源一致性 |

三个档位都保留容量和调用次数上限，不以发送所有资料或生成更长回答作为质量目标。“最高”提供更多核验机会，不保证结论正确，也不会扩大数据授权范围。

档位可以分别配置输入预算、输出预留、证据数量、回查深度和最大模型调用次数。若未来使用的模型支持推理强度参数，可通过适配层映射；不支持时明确显示实际策略，不能声称已启用不存在的能力。使用更贵模型需用户选择，不随档位静默更换。具体 token 数额待选定模型并做样本验证后确定。

本地导出也提供三种上下文包：标准为状态与摘要；高增加相关片段；最高增加按主题分组的证据索引和阅读顺序。本地助手按索引分批读取，不把“最高”包的所有文件一次拼进提示词。工具的导出档位不能自动控制外部聊天应用的模型、上下文窗口或收费方式。

## 5. 每次请求的预算流程

1. 明确问题、目标范围、质量档位和用户允许读取的资料。
2. 校验现有摘要有效性，先取当前状态、相关摘要与必要证据，去除重复片段；材料中的文字不是工具指令。
3. 计算或估算 token，计入系统指令、结构化工具定义、近期对话、证据，以及模型所需的输出/推理预留和安全余量。使用对应模型的计数能力；不把字符数当作通用精确 token 数。
4. 超限时先去掉重复和无关内容、缩减早期对话并读取摘要；必要约束、问题与关键反例不能静默截断。仍无法容纳时拆成有上限的分批分析，或请用户收窄范围。
5. 需要额外证据时，在本次总预算内展开；把证据读取、摘要生成、分析与综合的全部模型调用计入总额。禁止无界重试和递归总结。
6. 返回结论及来源，并记录读取范围、缺失或未展开内容、使用档位和实际消耗。预算不足时明确说明覆盖限制，不伪装成完整总评。

网站请求前可显示预计范围、token 和模型调用次数；费用只有在对应模型价格可核实时才估算，显示估算而非保证值。默认不会自动升档，也不会以升档替代缺失证据。回答长度是独立选项，标准模式也可以输出详细说明。

## 6. 存储、同步与评估关系

新摘要按版本增量同步；临时上下文包是可重新生成的缓存，不保存无数完整副本。正式总评保存结论及证据引用，不复制全部输入正文。原始资料遵循独立保留策略，生成摘要不会触发删除原件。

用户删除或更正证据时，必须处理其派生摘要和评估的影响；历史报告可标记已被修订或依据失效，隐私删除按选定范围清理内容。测试摘要、上下文包和临时评估也随测试批次清理，真实资料受到保护。

## 7. 最小实现与验收

先实现当前状态、阶段摘要清单、来源版本与有效性、标准上下文包；再实现高/最高模式的证据展开和分批核验。首期索引可基于空间、目标、时间、材料类型与明确引用，不强制引入向量数据库。

验证不同档位是否改善证据覆盖和减少遗漏，不只比较字数。回归案例应覆盖长历史续谈、用户改口、旧期限已取消、相互矛盾的材料、重复证据、缺失来源、中文与混合文件、最高档超预算、多调用累计费用、删除授权后的摘要失效。压缩后必须保留关键约束和未决问题，不把 AI 建议或自述变成既定事实。

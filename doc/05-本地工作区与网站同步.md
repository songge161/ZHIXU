# 本地工作区与网站同步

## 1. 目标与当前状态

用户可以把本地资料交给能够读取指定目录的 AI 助手整理，网站负责展示、调整和执行。当前原型已经实现手动选择目录、按记录写入 Markdown、从目录读取并预览替换；未实现目录监听、AI 自动回写、账号、云端同步或冲突合并。

工作区与设备无关。Mac 和 Windows 各自手动选择能访问的目录；记录用稳定 ID 识别，标题、路径或电脑变化不会改变记录身份。浏览器 `localStorage` 只是界面运行缓存，文件目录是可阅读、可迁移的本地工作区，云端接入后服务端保存已确认的共同版本。

## 2. 当前目录协议

```text
my-study/
  workspace.md
  _index.tsv
  goals/<id>.md
  actions/<id>.md
  progress/<id>.md
  evidence/<id>.md
  drafts/<id>.md
  reviews/<id>.md
  schedule/<id>.md
  schedule/settings.md
  graph/edges.tsv
```

每个业务记录单独保存。Markdown 元数据描述类型和稳定 ID，正文保留自然语言；`_index.tsv` 列出当前有效记录、路径和 SHA-256，并在一次写入的最后更新；`graph/edges.tsv` 保存关系边。行动推进记录写入 `progress`，日程和生活基线写入 `schedule`。没有一个包含全部业务数据的总 JSON 文件。

写入时先计算每条记录的内容哈希，只改写发生变化的文件。读取时重新计算哈希：与索引不同表示文件曾被用户或本地 AI 修改，解析及业务校验通过后列入预览，再由用户确认是否替换浏览器内容。索引之外的文件不自动视为删除或新增，避免误把临时文件带入工作区。

详细字段、图模型、进度算法和演进顺序见 [目标图与增量工作区设计](./12-目标图与增量工作区设计.md)。

## 3. 本地 AI 的衔接方式

1. 用户在设置页选择工作区并写入当前内容。
2. 本地 AI 先读 `workspace.md` 与 `_index.tsv`，再按问题读取相关目标、行动和证据。
3. 当前阶段，AI 可以在用户知情的情况下编辑独立记录文件；网站读取时展示外部变化。
4. 下一阶段，AI 输出带基础哈希的结构化操作提案，网站展示逐项差异，允许部分采纳。
5. 用户确认后，网站更新记录、关系与索引；被采纳的修改才进入未来的云端共同版本。

普通聊天回复不会自动写入网站。文件保存或监听事件也不代表用户已经批准计划变化。

## 4. 同步契约方向

- 身份：记录使用稳定 ID，不靠标题、文件名、设备编号或修改时间匹配。
- 操作：记录 `changeId、recordId、baseHash、operation、patch、createdAt`，重复提交保持幂等。
- 校验：服务端从登录会话判断归属，并检查父子关系、依赖环、字段范围、容量和基础版本。
- 冲突：一侧未变化可以快进；不同字段可以三方合并；同字段冲突保留双方值并请求选择。
- 删除：必须是显式操作并保留删除标记，不能把文件缺失当作删除。
- 附件：原始 PDF、图片等默认留在本地；选定上传后按内容哈希去重，数据库只保存归属和引用。
- 历史：已完成记录不被重排覆盖；范围变化和正式评估使用版本记录。

## 5. 实施顺序与验收

先稳定当前多文件协议和外部修改预览，再实现目标层级、通用关系边及环检测，然后实现 AI 变更提案、部分采纳和三方合并，最后接 HomeCC API 与现有线上数据库。自动监听只在协议和冲突处理稳定后加入。

验收需覆盖：改名后仍识别原节点、重复写入不改写未变化记录、目录外修改可见、非法字段和关系被拒绝、重复操作不重复创建、两端修改不会静默覆盖、删除不会被旧副本复活、未选资料不上传，以及测试批次清理后本地旧操作不能回流。

测试范围与清理规则同时约束本地草稿、附件、同步日志和云端记录，详见 [数据与测试治理](./02-数据与测试治理.md)。

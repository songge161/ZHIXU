# v0.1 本地原型使用与目录工作区

更新时间：2026-10-13。项目暂名“知序 · EDU”。本轮只操作此目录，未部署网站、连接云数据库或调用 AI API。

## 体验流程

1. 执行 `npm ci`、`npm run dev`，打开 http://127.0.0.1:4180/ 。根页是教育入口，规划属于 `/planner`。
2. 在规划页新建或调整方向，添加行动并记录完成。当前完成数只代表执行记录。
3. 保存讨论草稿，再手动确认并转为行动。当前没有 AI 自动回复或自动拆解。
4. 在资料页添加自述或选择文件。文本只读取前 48,000 字节并保存有限摘录；非文本文件只登记元信息，不上传原件。
5. 在阶段回顾页生成执行小结；预计时长不当作实际学习时长或能力证明。
6. 在接续页预览并下载 Markdown 讨论包，交给可以读取文件的本地 AI 会话。
7. 在设置页手动选择专用目录，点击“写入当前内容”建立工作区；目录被外部编辑后，点击“从目录读取”查看变化并确认载入。

## 目录与不同电脑

- 不读取硬件信息，也不生成设备序列号。稳定记录 ID 用于识别数据，电脑只负责访问用户选择的目录。
- 目录通过 `showDirectoryPicker()` 选择，句柄保存在当前浏览器 IndexedDB 的 `edu-workspace-local` 数据库。清除站点数据后需要重新选择目录，目录文件本身不受影响。
- Mac 与 Windows 可以各自选择本机目录，也可以选择双方都能访问的同步盘目录。系统路径和浏览器授权不能跨电脑复制。
- 数据按 `goals`、`actions`、`evidence`、`drafts`、`reviews` 分目录保存为 Markdown；`_index.tsv` 保存当前记录和 SHA-256，`graph/edges.tsv` 保存关系。
- 写入只改写哈希变化的业务记录，并最后提交索引。当前仍会更新入口说明和关系表。
- 读取会解析所有索引记录，再通过统一的数量、字段和关联校验。哈希不同的合法文件会在确认框中列出。
- 当前不监听目录、不后台同步、不自动删除索引外文件，也不自动合并浏览器和目录的并发修改。
- 目录选择需要安全上下文以及桌面版 Chrome/Edge 的 File System Access API；系统文件选择器和真实文件夹授权仍需人工验收。

Mac 示例目录为 `~/Documents/知序`，Windows 示例目录为 `D:\\学习\\知序`。建议先选择空目录，避免与其他软件生成的文件混放。

## 限制与容量

| 内容 | v0.1 限制 |
| --- | --- |
| 方向 / 行动 | 最多 40 / 500 |
| 资料 / 草稿 / 小结 | 最多 50 / 50 / 30 |
| 单文件登记 | 100 MB；不复制原文件 |
| 文本摘录 | 每份最多约 12,000 字符 |
| 讨论包标准 / 高 / 最高 | 最近 3 / 8 / 15 份资料；每份摘录 500 / 1800 / 3000 字符 |

浏览器 `localStorage` 保存界面运行缓存，内部采用 JSON 序列化；这不是对外交换格式，也不是目录中的总数据文件。长期可迁移内容以分记录工作区为基础。当前没有总 token 硬预算、语义检索或摘要质量评估，也没有跨标签页冲突处理。

## 验证与后续

`npm run build` 检查类型和生产构建。`npm test` 使用本机 Google Chrome 的隔离上下文，覆盖门户路由、行动和草稿持久化、多文件目录往返、内容哈希、外部修改提示、权限拒绝、文本边界、资料深度、手机布局、执行回顾和限定范围重置。目录测试使用内存句柄，不代表操作系统选择器已实测。

测试报告和截图位于 `test-results/`、`output/`，并已加入 `.gitignore`。本轮没有服务器测试数据。发布前按 `02-数据与测试治理.md` 清理示例、测试记录和附件。

下一步优先：多层目标和通用关系边 → 依赖环检测 → 证据关联与多维进度 → AI 变更提案和部分采纳 → 阶段摘要与上下文预算 → 后端增量同步。当前实现边界及算法依据见 `12-目标图与增量工作区设计.md`。

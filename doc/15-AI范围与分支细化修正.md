# AI 范围、分支与提案审阅

2026-10-14。真实日语规划提案暴露的问题：限定范围内的新草稿被统一判成越界；新建分支的临时 ID 不在既有节点集合内，导致同批行动无法采纳；上下文固定追加“先澄清”，使细化请求反复生成澄清任务。

## 本次行为

- `proposalScope.ts` 按选中操作构建候选父子关系，校验临时 ID、父分支依赖、原记录归属、迁移目标和环路。原范围边界仍保留。
- 草稿、资料和回顾新增可选 `spaceId`。限定范围内新建且未提供归属的辅助记录归入当前方向；已有全局记录不会自动被当成范围内记录。旧工作区可继续加载。
- 本地 Markdown 元数据和关系表保存归属；后续 AI 上下文会读取范围内辅助记录。草稿可手工调整归属，转为行动时带入所属方向。
- AI 按本轮模式细化、调整、评估或讨论；待确认信息允许作为暂定分支的假设，不再一律阻止建分支。提示要求复用已有内容、具体产出与完成标准，不编造截止日期和能力水平。
- 提案默认显示标题、归属、理由；正文和参数按需展开。漏选父节点等问题标在具体操作上，不能采纳存在校验问题的选项。
- 方向说明与进度规则折叠；修复里程碑误用大字号；路由切换回到顶部，总览长描述收为两行。

## 验证边界

自动化使用模拟 AI 响应验证多层结构、作用域、依赖、应用与持久化，不代表真实模型每次都会给出优质内容。保留人工审阅；没有自动采纳用户当前工作区的新计划，没有写入用户绑定的目录或线上数据库。

## 评估表达调整

针对真实回复中“关键未知未解除”、短 ID 堆叠和反复改写根说明的问题：评估优先用短段落直接回答已推进内容、当前阶段和下一步；尊重用户完成记录，不把未提供总结当作没做，不因上下文裁剪否定用户现实成果。单纯问进度默认不产生修改操作。提示要求自然语言字段使用名称，仅关联字段使用 ID。

提案界面额外解析已知完整 ID 和唯一的 8 位十六进制前缀，显示对应名称；前缀冲突时不猜测。缺标题的更新操作使用现有记录标题。仅改变展示，不修改关联 ID 或历史数据。模拟响应测试覆盖名称展示与 ID 不变，真实模型的措辞改进需要下一轮生成确认。

# 初级与普通用户体验复测

日期：2026-11-05。对象：EDU 本地规划原型。

这是一轮模拟两类用户的浏览器黑盒走查，不是两位真人参与的访谈。用户流程仅通过界面操作和界面结果验证；自动化浏览器使用隔离数据，不读取或修改日常使用的浏览器资料。对应脚本：`tests/usability.spec.ts`。

## 用户一：刚接触规划工具的初级用户

目的：不配置 AI、不理解权重，也能建立方向并完成第一件事。

路径：教育首页 → 打开学习规划 → 新建大方向 → 创建第一个行动，不填日期 → 今日行动 → 找到并勾选 → 刷新后回方向确认。

原问题：默认不填日期的行动不会进入原来的今日列表。创建成功后，用户切换到日常入口会以为行动没有保存。基线测试在寻找该行动时失败。

调整：日常页面增加“未排期行动”，明确可以不选日期就开始。已完成的本次操作暂时保留，方便取消勾选；刷新后从未完成队列中移出，仍可在所属方向查看。侧栏待办数量同时统计到期及未排期待办。

结果：完整流程通过，刷新后完成状态保留。空方向不显示没有实际内容的行动状态、记录和资料工具。

截图：[未排期行动入口](../../output/usability-novice-today.png)。

## 用户二：希望提高日常效率的普通用户

目的：找到下一件事，补充一次记录和资料，然后完成行动。

路径：方向总览 → 研究能力方向 → 查看行动 → 展开状态，改为进行中 → 展开推进记录，保存摘要 → 关联笔记 → 勾选完成 → 刷新核对状态、记录和资料。

原问题：方向详情在主要行动之前展示验收和节点状态，又把同一个行动重复列在状态、过程、资料、推进方式四套面板中。用户需要穿过较长的页面才能处理日常工作。

调整：默认顺序为进度、当前行动、子方向；其余合并为四个按需展开的入口。主要行动行显示推进方式、执行状态和可选时长，分量、难度明细留在进度说明或编辑中。

结果：默认详情中行动不再以多套展开列表重复出现；所有辅助入口仍可使用，记录、完成状态和资料绑定在刷新后保留。

截图：[默认方向详情](../../output/usability-detail-1280.png)、[记录和资料展开状态](../../output/usability-ordinary-expanded.png)。

## 窗口兼容性

| 视口宽度 | 使用场景 | 本轮结果 |
| --- | --- | --- |
| 360、390 | 窄屏手机 | 常用路由、日历切换和行动编辑通过 |
| 768、820 | 平板或电脑分屏 | 通过；820 像素问题已修复 |
| 1024、1280 | 小尺寸电脑、笔记本窗口 | 常用页面及编辑通过 |
| 1440、1920 | 桌面、大屏 | 常用页面及编辑通过 |

基线在 820 像素宽的方向详情检测到 21 像素横向溢出。调整进度卡片列宽、断点、标题换行和内容收缩后，八档宽度的九条主要路由均未检测到页面横向溢出。日程日/周/月切换及弹窗宽高也纳入检查。

另以 1024×600 的短窗口创建长方向名称和长行动，切换到 820、390 像素宽后继续编辑并保存。检查了弹窗的边界、主按钮可操作性、超长文字换行和侧栏收起后的空间。

## 验证与边界

- 本轮生产构建通过；全量 54 项回归通过，包含原有规划、AI 模拟提案、目录、资料、验收、进度预览与日程。
- 新增用户旅程和布局场景共 11 项。原有测试按新的折叠入口操作，不绕过界面直接打开折叠内容。
- 视口检查由本机 Chrome 完成，不代表已经在实体 Windows、Mac、多种浏览器、系统缩放和不同屏幕密度上分别验证。
- 未调用付费 AI，也未验证本轮新增之外的真实 AI 回复质量、文件系统权限和云端能力。

# 知序 EDU 黑盒产品体验测试报告

测试日期：2026-10-14  
测试身份：普通学习者 / 首次使用者视角  
测试方式：只看页面、文案、交互和用户可见结果，不评审实现代码

## 一、总体结论

当前原型已经形成了比较完整的“方向 → 行动 → 资料 → 回顾 → 调整”闭环，视觉风格统一，桌面和手机页面都能正常使用；核心页面没有发现阻塞级错误，已有回归用例 20/20 通过。

最需要优先解决的不是单个按钮或样式，而是首次使用时的信任和理解成本：用户一进来就会看到可编辑的示例数据，但“示例”和“自己的数据”的边界不够醒目；同时数据默认只在当前浏览器保存，目录工作区和 AI 配置又需要用户主动理解。对于一个长期记录学习过程的产品，这两点会直接影响用户是否敢开始、是否相信数据不会丢。

## 二、测试范围与环境

- 入口：教育门户、学习总览、今日行动、资料与证据、阶段回顾、AI 规划、接续与同步、设置。
- 关键流程：创建大方向、创建子方向、添加/调整行动、完成行动、记录草稿、写 Markdown、导入资料、生成执行小结、预览接续包、配置 AI 接口、恢复示例、异常路由。
- 视口：桌面 1440×1100；手机 390×844。
- 结果：所有主要路由可加载；探索式检查未见页面报错；手机页面未发现横向溢出；未知路由能回到学习总览。
- 自动化回归：`npm test` 共 20 个用例全部通过。

## 三、问题清单

优先级含义：P1 会明显影响首次使用、数据信任或核心闭环；P2 会增加理解成本或降低效率；P3 属于细节和后续体验提升。

### P1-01：示例数据与真实用户数据的边界不够醒目

**现象**

首次进入工作台就能看到 3 个大方向、今日行动、资料和示例回顾。页面只在上方用较小的“本地原型 · 示例可编辑”提示，示例记录本身也和真实记录一样提供“调整、删除、完成”等操作。

**用户影响**

首次使用者可能把“研究生阶段 · 研究能力”“文献阅读笔记.md”等误认为已经存在于自己的空间，或者误操作示例后不确定哪些内容是真实数据。产品的第一印象会从“帮我开始”变成“我需要先清理别人留下的内容”。

**建议**

- 首次进入增加明确的选择：`使用示例体验` / `从空白开始`。
- 示例模式使用明显的“示例数据”横幅或统一角标，并提供一键清空示例。
- 示例记录的操作按钮默认弱化，或在首次操作时说明“这是示例记录”。
- “恢复浏览器内示例”继续保留确认弹窗，但补充“会覆盖当前知序浏览器数据”的说明。

### P1-02：本地保存和数据安全提示出现了，但没有形成首次使用决策

**现象**

页脚多处显示“数据保存在当前浏览器 · 云端未接入”，设置页也说明需要手动选择目录；但用户可以在尚未选择目录的状态下直接创建行动、草稿、回顾和资料。没有明显的首次提示告诉用户：当前数据还没有独立文件备份，清理浏览器数据可能造成损失。

**用户影响**

长期学习记录属于高沉淀数据。用户可能以为“已经保存”就等于已经写入自己的文件或云端，直到更换浏览器、清除站点数据或换设备才发现无法恢复。

**建议**

- 首次创建第一条真实记录前，用非阻塞提示明确当前保存位置和风险。
- 工作台顶部显示状态：`仅浏览器保存`、`已绑定目录`、`最近写入时间`。
- 增加“导出完整工作区”而不只是单篇 Markdown 下载，至少覆盖方向、行动、草稿、资料和回顾。
- 设置页增加“如何备份 / 如何恢复”的最短说明和最近一次成功写入结果。

### P1-03：AI 未配置时能看到完整流程，但下一步不够直接

**现象**

AI 规划页的范围选择、四种工作模式和输入框都可见，但生成按钮是禁用状态，页面下方只用一句文字提示“请先到 `/settings` 添加并启用一个 AI 接口”。这个路径不是可点击的行动按钮，用户需要自己打开导航、找到设置、填写技术参数，再返回 AI 页面。

**用户影响**

用户会先以为 AI 功能坏了，或者不知道“AI 规划”是可选能力还是使用前置条件。对于第一次使用者，Base URL、协议和模型 ID 也会进一步放大挫败感。

**建议**

- 将提示改成明显的 `去设置 AI 接口` 按钮，并保留 `先用手工规划` 的替代路径。
- 未配置状态直接告诉用户：手工规划、资料记录和回顾不需要 AI。
- 设置页增加“测试连接”与可读的成功/失败原因；保留本地模型无 API Key 的能力，但在界面上解释适用场景。
- 配置完成后回到 AI 页时保留用户刚才选择的方向和模式。

### P2-01：产品术语层级较多，用户需要自己理解数据模型

页面同时使用“大方向、方向、子方向、节点、计划、阶段、项目、分支、行动、资料库、总文件库”等称呼。比如总览把根节点都放在“大方向”下，添加行动时字段叫“所属计划或分支”，AI 页面又叫“跟进范围”。这些词在设计上有依据，但对首次用户来说缺少一条简单的主线。

建议先固定一套面向用户的主语言，例如：`方向 → 计划 → 行动 → 记录`；“节点类型、权重、难度、分支”放进“高级设置”或用一句话解释。资料库则明确区分“当前方向资料”和“总资料库”。

### P2-02：总览卡片的信息密度和“根方向”含义不完全一致

总览标题是“我的大方向”，但示例中“我的第一篇研究论文”也作为同级卡片出现。用户可能不知道这里既能放长期方向，也能放论文项目或具体计划；卡片下方同时展示进度、行动数、里程碑和编辑入口，阅读顺序不够明确。

建议在总览中明确“这是顶层入口，不一定都是长期方向”，或按“长期方向 / 项目”分组；卡片主按钮统一为一个主要动作，把编辑放到次要位置。

### P2-03：创建行动时的高级字段过早出现

添加行动的表单一次展示了所属计划、日期、预计分钟数、行动分量、行动难度、行动总结和文件导入。对只想记下一个小行动的用户来说，核心任务是填写标题、归属和日期，其他字段会增加负担。

建议默认只显示标题、归属、日期和预计时间；“分量、难度、总结、导入文件”收进“补充执行信息”。保存后再引导用户补充，而不是第一次就要求理解加权进度模型。

### P2-04：资料页的“保存记录”和下载行为需要更明确

未选择工作区目录时，写 Markdown 弹窗默认勾选“同时下载 .md 文件”。这是合理的兜底方案，但用户点击“保存记录”时可能没有意识到浏览器会弹出下载；页面提示也没有在按钮附近说明文件会保存到哪里。

建议根据当前状态明确区分按钮文案：`保存并下载 Markdown`、`仅保存到浏览器`，或者首次保存时解释下载位置。目录已绑定时则改为 `保存并写入工作区`，让保存结果与实际落点一致。

### P2-05：手机端整体可用，但辅助文字偏轻、页面较长

390×844 下主要页面没有横向溢出，菜单、卡片和表单都能排布；但资料页、设置页和接续页需要较长滚动，许多说明文字使用低对比度的浅灰/浅绿，移动端快速扫读时容易被忽略。页面顶部只有简短面包屑，长页滚动后回到关键操作需要较多手势。

建议提高次级文字和页脚状态的对比度；对资料、设置、接续页考虑分段折叠或粘性区块；长列表增加“回到顶部”或固定当前主要操作。

### P3-01：删除后的可恢复性可以更好

删除方向、行动、资料和回顾前有确认，这是安全的；但删除完成后主要只显示短暂提示，没有撤销入口。长期学习记录的误删成本高，尤其方向删除会连带删除下级行动。

建议在删除成功提示中提供短时间 `撤销`，或在确认弹窗内展示受影响记录数量并提供导出/备份入口。

## 四、做得比较好的地方

- 核心路径连贯：从总览进入方向，再安排行动；今日页可以记录草稿并转成行动；资料和回顾都有独立入口。
- AI 提案采用“先生成、逐条审阅、再采纳”的方式，页面明确表达“AI 不会直接修改数据”，这降低了用户对自动改写的担忧。
- 接续包预览显示来源、范围、资料深度和截短说明，用户能知道将要带走什么上下文。
- 表单在桌面和手机都能使用，方向选择器支持搜索和键盘操作；未找到方向、无 AI 配置、未选择目录等状态都有一定提示。
- 页面视觉语言统一，绿色层级、卡片、图标和按钮风格一致；未知路由也有可理解的返回入口。

## 五、建议的下一轮产品迭代顺序

1. 先处理首次进入：示例/空白模式、保存位置状态和数据备份提示。
2. 再处理 AI 未配置引导：可点击去设置、测试连接、手工替代路径。
3. 收敛用户术语和总览信息架构，减少第一次使用时需要学习的概念。
4. 把行动表单的高级字段后置，优化资料保存的结果反馈。
5. 最后处理手机长页面、文字对比度和删除撤销等细节。

# 学习证据与多层评估

## 1. 需求与定位

2026-10-13 用户提出：持续投入文件、自述等材料，逐步评估达到的程度，并支持多个总评。以下为待实现方案；用户确认了需求方向，具体评分标准和页面仍可调整。

规划工具形成“目标 → 行动 → 学习证据 → 评估 → 计划调整”的循环。评估描述某一时间、某个目标下有依据的能力状态，不把一个人压缩为固定总分。任务完成、投入时间、成果质量与能力掌握分别呈现。

## 2. 低操作成本的材料收集

学习空间内提供统一入口“补充材料 / 说说进展”。用户可以拖入文件，或直接写“这周做了什么、哪里卡住、我认为掌握了什么”；关联当前项目即可保存，不要求每次填写评分表。

| 输入 | 例子 | 用途与边界 |
| --- | --- | --- |
| 参考资料 | 教材、别人写的论文、课程提纲 | 定义学习内容和标准；拥有或上传资料不代表已掌握 |
| 个人成果 | 笔记、解题过程、实验记录、代码、论文草稿 | 作为能力判断依据；标明独立完成、借助工具或合作完成 |
| 自述 | 理解、困难、反思、口头解释的文字记录 | 保存主观状态及待验证判断，不自动升级成已证明能力 |
| 验证记录 | 测验、复现结果、迁移题、导师反馈 | 补强或修正已有判断；用户转述的反馈标记为转述 |

助手可以建议材料类型、关联目标和摘要，用户能修正。无法解析的文件保留为待处理，明确缺页、扫描质量、未读取附件等限制，不生成“已完整阅读”的假结论。首期优先文字、Markdown 与可提取文本的 PDF；图片、扫描件、音视频后续扩展。

## 3. 逐步形成能力画像

先针对目标定义少量可观察维度和达到标准，再找材料支撑。例如论文项目可分别看问题表述、文献比较、实验设计、结果分析和写作；语言学习可分别看阅读、听力、表达与实际测试。不同领域使用不同量表，首期从一个项目模板开始。

能力层级可用“能够解释 → 借助提示完成 → 独立完成 → 迁移应用”作为可编辑模板；证据不足单独标记“待验证”，不是最低分。每一维度保存：

- 当前判断与目标标准，以及该标准的版本。
- 引用的材料版本和位置，例如 PDF 页码、笔记段落、代码文件和行号。
- 来源性质：用户自评、AI 初评、外部反馈；判断理由、反例与尚未覆盖的部分。
- 证据充分度和待验证问题，采用可解释描述，不输出未经校准的精确置信概率。
- 下一步最小验证行动，例如独立解释一个概念或补一个对照实验。

同一证据可以关联多个维度，但重复上传或多份报告引用同一材料，不算新增独立证据。用户能更正错误和提交异议；保留原判断与更正记录。用户接受报告不意味着报告变成客观考试成绩。

## 4. 多个总评并存

“多个总评”暂按三个方向设计，避免只保留最后一份报告：

| 方向 | 示例 | 规则 |
| --- | --- | --- |
| 时间 | 入门基线、本周、月度、阶段结束 | 保存历史快照，显示新证据带来的变化 |
| 范围 | 一篇论文、一个学科、语言阶段、研究生方向 | 可并存，父级不直接平均子级百分比 |
| 视角 | 个人自评、AI 评估、导师反馈、综合报告 | 保留来源及分歧，不把多个模型同意当作独立验证 |

每份报告固定记录评估范围、截止时间、材料清单、标准版本、结论、缺口、下一步建议，以及作者或模型来源。综合报告可引用多份分项评估，但需说明选取与汇总口径；不同时期或量表不同的评分不直接连成能力增长曲线。标准变化时保留旧口径，另行解释可比部分。

默认展示各维度的证据和状态。只有明确配置了可解释的指标、权重与覆盖率才显示总分；缺失维度不自动计零或计满分。研究生方向的总评可按研究能力、课程、表达和阶段成果分别总结，不强制生成一个“完成百分比”。

## 5. 本地与网站流程

本地工作区新增 `evidence/` 索引、`rubrics/` 评估标准、`assessments/` 报告；原始资料仍放在用户选择的本地材料目录。索引使用稳定材料 ID、内容哈希、版本和相对位置，不依赖绝对路径。

用户把所选材料和上次评估交给本地助手，助手生成可阅读报告与标准导入包。网站沿用统一预览和应用流程，允许只导入报告与选定摘要、引用，不强制上传原文件；本地独有引用在网站显示“原件保留在本地”，不能伪装成网站已验证文件。报告的文字解释本身也可能含私人材料，预览需覆盖这些内容。

网站 API 是可选评估入口，用户明确触发评估才发送选定材料与必要上下文。上传文件、同步报告和浏览进度本身不触发模型付费请求。材料中的指令视为资料内容，不能改变助手的权限或触发额外工具执行。

新增材料先进入资料库，可提示“有新材料，可更新评估”；不每上传一份就重算所有总评。评估建议转为计划变更提案后，由用户选择应用；不因 AI 给出较低评价自动删除任务或改变截止日。

## 6. 示例

用户添加论文草稿、两次实验结果，并说“方法基本理解了，但不知道如何证明比基线更好”。

报告可以分别指出：研究问题表述有草稿支持；实验比较仍缺对照；对方法的独立理解目前主要来自自述，待通过解释或复现验证。下一步建议为补充基线实验，并说明将验证哪个判断。

这次报告是该论文的阶段总评，也可作为月度研究进展报告的一个来源；不会因此直接把整个研究生阶段标为某个完成百分比。

## 7. 实施与验收

首期只需材料列表、文字自述、可配置的少量评估维度、报告历史和本地导入导出。规划空间下建议增加 `/planner/spaces/:spaceId/evidence` 和 `/planner/spaces/:spaceId/assessments`；已有 `/planner/reviews` 继续用于执行复盘，能力评估可被复盘引用。

候选数据包括 `progress_evidence`、材料版本与目标关联、`progress_rubric_versions`、`progress_assessments`、维度判断及证据引用。最终表名在实现时确定。原始资料、提取文本、AI 判断和用户更正分开记录；报告引用固定版本，文件替换不悄悄改变旧报告依据。正式报告保留快照，复评生成新报告；显式删除资料时按选定范围清理派生文本和报告内容，不能以“保留快照”为由阻止用户删除私人数据。

验收重点：参考材料不等于个人成果、自述与验证记录有区别、无证据可保持待验证、引用可追溯、重复材料不抬高评价、不同量表不误比、多个总评能共存、修正有历史、不同账号隔离、无 API Key 仍可导入报告，以及测试材料和派生评估可按批次清理。真实材料不得因开发阶段而当作测试垃圾删除。

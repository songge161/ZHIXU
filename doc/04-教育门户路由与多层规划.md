# 教育门户路由与多层规划

## 1. 已确认定位（2026-10-13）

用户希望未来教育首页具有类似大学门户的组织方式。个人规划是附属栏目，根首页不是计划主页。当前先实现本地规划功能，教育门户仅保留轻量入口；院系、课程、资源等属于未来想法，不代表已确定功能需求。

## 2. 路由建议

| 路径 | 路由名称 | 职责 |
| --- | --- | --- |
| `/` | `edu-home` | 教育门户首页，开发期可只展示栏目入口 |
| `/login` | `edu-login` | 账号登录 |
| `/planner` | `planner-home` | 个人规划总览 |
| `/planner/spaces/:spaceId` | `planner-space` | 一个方向或项目的层级目标与进度 |
| `/planner/spaces/:spaceId/items/:itemId` | `planner-item` | 阶段、学科、论文或任务详情 |
| `/planner/today` | `planner-today` | 今日行动与习惯 |
| `/planner/schedule` | `planner-schedule` | 日、周、月日程与时间预算 |
| `/planner/reviews` | `planner-reviews` | 阶段复盘 |
| `/planner/materials` | `planner-materials` | 资料、证据与自述 |
| `/planner/ai` | `planner-ai` | 按范围生成和审核 AI 规划提案 |
| `/planner/sync` | `planner-sync` | 导入、导出、同步和冲突处理 |
| `/settings` | `edu-settings` | 手动选择工作区目录与调整讨论资料深度 |

不得把 `/` 重定向到 `/planner`，或把全站布局写成计划专用布局。代码模块建议为 `portal`、`planner`、`auth`；浏览器链接使用稳定 ID，标题变化不改变链接。以上子路由为建议契约，可在实现前细化。

2026-10-14 原型已实现 `/`、`/planner`、`/planner/spaces/:spaceId`、`/planner/today`、`/planner/materials`、`/planner/reviews`、`/planner/sync`、`/settings`。登录路由尚未实现；节点编辑仍使用对话框。规划首页只承担方向总览和入口，点击“查看方向”进入独立详情页，在详情页展开子方向目录、查看当前节点的直接行动并继续发散。同步页当前支持讨论包与手动目录工作区，尚无云端同步和冲突合并。

2026-11-02 校准：当前实现已补充 `/planner/schedule` 和 `/planner/ai`。日程支持日、周、月视图、生活基线、工作日/节假日与剩余预算；AI 支持整个工作区或任意节点后代范围，并在逐项审核后应用提案。账号、云端同步、冲突合并和正式部署仍未实现。

## 3. 多尺度规划

学习空间作为容器，内部使用可嵌套节点，不为每一种学习场景单独建一套系统，也不强制固定三层。

| 尺度 | 示例 | 主要衡量方式 |
| --- | --- | --- |
| 长期方向 | 研究生阶段、大领域学习 | 阶段成果、能力与毕业要求 |
| 阶段目标 | 考研、语言能力提升 | 阶段测评、目标分数、里程碑 |
| 学习或研究项目 | 单学科、一篇论文 | 知识点掌握、实验结果、稿件阶段 |
| 行动与习惯 | 阅读、实验、复习、每日练习 | 完成记录、投入时间、重复频率 |

节点类型可采用方向、目标、项目、里程碑、任务；习惯单独保存重复规则和每次完成记录。执行项可关联已有主站任务，但保持稳定身份，不能因为移动日期或换计划版本而复制完成事实。

## 4. 多变计划的规则

- 长期保持方向和成果目标，近期再拆到天或周；不要求一次排完整个研究生阶段。
- 支持暂停、降低工作量、重新安排、拆分、合并和保留未排期任务。
- 用户可锁定截止日或指定计划项，AI 重排时尊重锁定与可用时间；冲突时给出取舍建议。
- 计划版本记录“原来想做什么”；执行记录描述“实际做了什么”，两者分别保存。
- 耗时、任务完成率、能力测评和成果是不同指标。不能用学习时长或勾选数量直接推断掌握程度；没有可靠指标时显示未知。
- 父级汇总需定义口径和权重，避免父子节点重复计数；习惯显示期间完成率，不计作一个永远无法完成的目标。当前原型使用归属树递归汇总行动完成数，后续再引入里程碑权重和证据覆盖。

当前节点模型使用 `Space.parentId` 和 `Space.kind`，其中 `kind` 可区分方向、计划、阶段、项目和分支；写入前校验父节点存在且不形成环。删除节点时会明确确认，并级联删除其后代节点及归属行动。

产品入口将根方向和子方向分开：根方向通常由用户在总览手工建立；详情页的主要动作是继续细化子方向、计划、阶段、项目或分支。AI 默认沿当前范围的父节点创建细化项，只有用户明确提出时才创建根方向。

节点与行动都提供 `weight`（1–100）和 `difficulty`（1–5）。同一父节点下的分支按 `weight` 归一化后分配贡献；节点同时拥有直接行动和下级节点时，直接行动执行占 60%，下级节点占 40%。方向、计划、阶段、项目、分支分别使用递减曲线，越上层越需要更充分的推进才能增加同样的显示分数。

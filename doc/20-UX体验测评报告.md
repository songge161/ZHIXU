## 1. 测评方法

- **黑盒操作**：Chrome 桌面端，390 / 768 / 1440 三档视口，走完"门户 → 工作台 → 方向 → 行动 → 日程 → 资料 → 回顾 → AI → 设置"全路径；键盘-only 走查 Tab 序列；刷新验证 localStorage 持久化。
- **工程验证**：项目自带 Playwright 套件全量运行；生产构建并记录体积与耗时。
- **量化手段**：读取 computed style 计算 WCAG 对比度；统计字号分布与可交互元素实际尺寸；模拟 Tab 序列检测模态框焦点陷阱、移动抽屉背景可聚焦元素数量。
- **局限**：单人、单浏览器（Chrome）；未做 VoiceOver / NVDA 读屏实测；未做真实用户测试；结论基于 DOM 度量与交互验证，非逐像素视觉评审。

## 3. 做得好的地方（建议保留的设计决策）

1. **安全默认与可逆性**
   AI 提案逐条审阅、字节预算显式展示（16,235 / 49,152）、未配置连接时生成按钮禁用、导入目录需二次确认、删除均有确认、页脚明示"数据保存在当前浏览器 · 云端未接入"。这是典型的 *safe-by-default + 状态可见性*，比多数同类原型成熟。

2. **解释性优先于数字**
   方向详情页把进度计算摊开：权重归一化、难度修正、直属行动与子方向 60/40 分配全部可见，并明确写"执行进度不等同于能力水平"（`src/App.vue:810`）。主动防止数据对用户形成压迫，是专家级细节。

3. **渐进披露用得克制**
   统计折叠在 `<details>` 中、完成标准默认收起、空状态永远伴随"下一步"按钮（"这一天还没有日程。留出空白也是一种安排" + 添加按钮），没有把空白页变成填空题。

4. **DirectionPicker 是组件级范本**
   `src/components/DirectionPicker.vue` 完整实现 combobox 模式：`aria-activedescendant`、方向键 / Enter / Esc、焦点回归触发器、IME 组合输入保护、移动端 16px 字号防 iOS 缩放、`prefers-reduced-motion` 降级。

5. **响应式完整性真实成立**
   不是"没崩"，而是八档宽度（360–1920px）逐一验证零横向溢出；移动抽屉、月历网格、主要控件 48px 触控均已落实。

6. **性能基线健康**
   CLS 0、首屏约 298ms、gzip 后资源总量约 136KB（JS 113KB + CSS 23KB），本地优先架构下没有为框架付出不必要的代价。

## 4. 问题清单

### 4.1 P0 — 会实质伤害可用性 / 可访问性

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| P0-1 | **字号与对比度系统性不足** | 页脚 9px `#abb39e` 实测对比度 ≈ **2.0:1**；面包屑 **1.67:1**；月历条目标注 9px；全站 8–11px 声明遍布 `style.css` / `schedule*.css` | 建立最小字号阶梯 12/13/14/16/20/28，正文 ≥13px、辅助信息 ≥12px；次要文字色统一到 ≥`#6b7768`（对 `#f7f8f5` 约 4.6:1） |
| P0-2 | **行内触控目标过小** | 日程行"调整"按钮实测 **24×19px**，checkbox **19×19px**；低于 WCAG 2.2 的 24×24 底线，远低于 HIG 的 44px | 视觉尺寸可不变，用 `::after` 扩展点击区至 24×24（移动端 44×44）；行内文字链补 padding |
| P0-3 | **模态框焦点逃逸** | 25 个 Tab 位置中 **2 次落到 `BODY`**；`<dialog>` 未 trap，关闭后焦点未归还触发元素（`src/App.vue:872` 起） | 对 dialog 背景加 `inert`；`@close` 时 focus 回触发器；必要时补 focus trap |
| P0-4 | **无逐页 `document.title`** | `src/main.ts` 11 条路由共用默认标题，无 `afterEach` | 路由 `afterEach` 写入 `document.title = 页面名 + ' · 知序'`，成本约 3 行 |
| P0-5 | **无 skip link** | 键盘用户每次需 Tab 穿越约 30 个导航项才能到主内容 | 加"跳到主内容"链接（3 行 CSS + 1 个 `<a>`），仅键盘聚焦时可见 |

### 4.2 P1 — 一致性与交互品质

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| P1-1 | **移动抽屉背景仍可聚焦** | `src/App.vue:770` backdrop 后仍有 **9 个 tabbable** | 抽屉打开时对主内容加 `inert`，或焦点圈定在抽屉内 |
| P1-2 | **表单只有原生校验** | 必填为空仅出现浏览器气泡，无 inline error、无 error summary | 提交时统一校验 + 字段级提示 + 顶部 error summary，与视觉系统一致 |
| P1-3 | **删除用 `window.confirm`** | 行动 / 日程 / 草稿 / 资料 / 回顾均调用原生 confirm | 改为设计系统内 ConfirmDialog，并提供 5 秒"撤销"toast |
| P1-4 | **同目的地三套 CTA 文案** | `src/App.vue:761` "进入工作台"、`:763` "打开我的学习规划"、`:765` "进入规划空间"，全部指向 `/planner` | 建立 5 词 CTA 词汇表，一个入口只保留一个主文案，其余改次级样式 |
| P1-5 | **文案瑕疵** | 月视图统计"**项已排安排**"（`src/App.vue:798`）；时长存在 `30 分钟` 与 `1 小时 30 分` 两条格式化路径（行动行手写 `${task.minutes} 分钟`，绕过 `minutesLabel`） | 修正错字；全量替换为 `minutesLabel` 统一格式化 |
| P1-6 | **日程行双击编辑** | `src/App.vue:799` `@dblclick` 为 pointer-only；行内"调整"未加 `aria-label`（资料/回顾卡片已加，规范未落地） | 双击作为增强而非唯一路径；为行内按钮统一补 `aria-label`，可用 `vuejs-accessibility` lint 固化 |

### 4.3 P2 — 债务与风险

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| P2-1 | **DEV 环境 IP 链接渲染进门户页** | `src/App.vue:24` + `:763`，开发时显示 `192.168.50.240:4180` | 仅在显式 `?lan=1` 时显示，避免截图外发泄露内网地址 |

## 5. 专业建议（按投入产出排序）

### 第 1 步 · 两天内可完成的"地基修复"

1. 字号阶梯 12/13/14/16/20/28；次要文字对比度 ≥4.5:1。
2. 路由 `afterEach` 设置页面标题；加 skip link。
3. dialog 背景 `inert` + 关闭归还焦点；行内按钮点击区 ≥24×24（移动 44×44）。
4. Playwright 接入 `@axe-core/playwright`，三行代码把上述问题固化为 CI 门禁。

### 第 2 步 · 一致性收敛

1. CTA 词汇表：一个入口只留一个主文案。
2. 时长格式、删除确认各自收敛为唯一实现；删除加撤销 toast。
3. 把"资料卡片加了 aria-label、日程行没加"这类差异写成 lint 规则。

### 第 3 步 · 架构与验证纪律

1. 按路由拆子视图 + 懒加载，先瘦身 App.vue 再谈新功能。
2. 设备矩阵补 Firefox 与 Safari（目录选择器除外）。
3. keyboard-only、`prefers-reduced-motion`、axe 三项纳入每次提交。
